# Support

Thanks for using a KindStack project. Here is where to go depending on what you need.

## Something is broken

Open an issue in the repository where you hit the problem, using the **Bug report** template. Include what you expected, what actually happened, and enough detail for someone to reproduce it — version, platform, and the exact command or steps.

Bug reports belong in the specific project's repository, not here. This repository only holds org-wide defaults and nobody watching it can debug your issue.

## You want a feature or have an idea

Open an issue using the **Feature request** template in the relevant repository. Describe the problem you are trying to solve before proposing a specific solution — it usually leads to a better outcome.

## You have a question about how to use something

Start with the project's `README.md`. It is the most likely place for an answer, and if the answer should have been there but wasn't, that is worth an issue on its own.

If the README doesn't cover it, open an issue in that repository and ask. Questions that keep coming up tend to become documentation.

Some of our products also ship their own support page — for example, `recipeme-site` and `frameart-site` each serve a `support.html` with product-specific help. If you arrived from one of those products, that page is the better starting point.

## You found a security vulnerability

**Do not open a public issue.** See [SECURITY.md](SECURITY.md) for how to report it privately.

## Response expectations

These are small projects maintained by a small group of people, largely in their spare time. We read everything that comes in, but replies may take a while. A clear, reproducible report will almost always get a faster and more useful response than an urgent one.

## Contact

For anything that doesn't fit an issue, email **[hello@codekind.net](mailto:hello@codekind.net)**, or visit [codekind.net](https://codekind.net).

Some projects list their own contact address in their README. For questions specific to one of those projects, that address will reach the right people faster than the general one.

Please keep bug reports and feature requests on GitHub rather than email — issues are visible to other users hitting the same problem, and they don't get lost.
